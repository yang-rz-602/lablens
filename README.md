> **数值判定 100% 交给确定性代码，语言模型只负责把结果翻译成人话；没有参考区间时，系统拒绝判断。**

## 为什么做这个

做之前先把这块地摸了一遍（含 GitHub 开源生态与国内外竞品调研）。结论是：

**红海**：通用医疗大模型（5k★ 级、大面积停更）、OCR 与版面还原（PaddleOCR 89k★ / MinerU 79k★ / docling 66k★）、
"上传报告 → LLM 生成一段解释"的同质 Demo（10 余个，多在 0–6★、约一半无 LICENSE、基本没有评测）、
FHIR 数据通道（smart-on-fhir、HAPI、wso2 已够用）。
国内 C 端更是全面免费且高度同质：红黄绿灯、白话化、行动清单是同一套语言。

**空白**：

| # | 空白 | 本项目对应 |
|---|---|---|
| 1 | 中文检验报告 + **参考区间代码判定**（无公开中文区间规则库） | `core/rules.py` + `data/indicators_*.yaml`（95 项，来源标注到卫生行业标准） |
| 2 | **字段级溯源 + 判读依据**（中文为零） | `decision_trace`：每个判定记录用了哪条区间、来自哪里、跨过哪个界 |
| 3 | **中文检验报告评测集**（不存在） | `evals/` 20 份合成报告 / 276 项，含 4 个危急值 case |
| 4 | **确定性判读工具的 MCP 封装**（生态里全是 FHIR 数据通道） | `mcp_server.py`，零依赖手写 JSON-RPC |
| 5 | 危急值分级 + 输出护栏 | `critical` 阈值 + `core/guard.py` 正则确定性拦截 |

所以定位很明确：**不做第 11 个解读 Demo，做"中文检验报告的确定性判读层 + 可溯源 + 评测集"。**

## 三条硬约束（这是本项目的全部价值）

### 1. 数值判定完全去 LLM 化

偏高/偏低、危急值识别、单位换算、性别年龄特异区间——全部由确定性代码完成，可单测、可复现、可审计。

**依据不是直觉，是文献：**

- **Meyer 等**（*Frontiers in Artificial Intelligence* 2025, [DOI](https://doi.org/10.3389/frai.2025.1681979)）在 **246,842 个参考区间**、726,000 次请求上测得：大模型自报的参考区间**下限平均变异系数 26.5%**（IQR 7.35–129.01%）。
- **Lab-AI**（[arXiv:2409.18986](https://arxiv.org/abs/2409.18986)）实测 GPT-4-turbo **无检索时参考区间检索准确率仅 42.9%**，加检索后 0.995。
- 一对特别有教育意义的对照：Girton 等（*Clin Chem* 2024）发现 ChatGPT 的回答被 **75.9% 的评估者偏好**；
  而 Meyer 等（*CCLM* 2024）测得同样的模型**恰当性仅 51–64%、22–33% 高估病情**。
  → **"讨人喜欢"和"临床正确"是两件事**，所以本项目的卖点刻意不是"回答得像医生"。

### 2. 没有参考区间就拒绝判断

优先级：**报告单自带区间 > 内置知识库 > 拒绝判定**。

这不是保守，是必须的——不同医院用不同仪器与试剂，参考区间本就不同，报告上印的才是对这份结果有效的。
Meyer 等那篇的结论原文就是：在用户未提供参考区间时，**AI 应被训练为拒绝进行实验室解读**。

### 3. 输出护栏是代码，不是提示词

诊断结论、用药与剂量、处方相关表述由**正则确定性拦截**，不依赖模型自觉
（《互联网诊疗监管细则（试行）》第 13、21 条）。

这条有反面教材：FDA 2025-07-14 给 WHOOP 的警告信明确表示，
产品标签上的"非医疗器械、不能诊断"**不足以推翻器械认定**。
→ **免责声明不能替代对输出内容本身的克制。**

```
│ 只抄不算：参考区间原样照抄，抄不到就 null，不许自己补区间     │
│ 输出受 JSON Schema 约束，并二次 Pydantic 校验              │
└──────────────────────────────────────────────────────────┘
        │  RawLabReport
        ▼
┌──────────────────────────────────────────────────────────┐
│ Stage 2  规则引擎（100% 确定性，无 LLM，可穷举单测）        │
│  · 指标名解析（95 项字典 + 别名索引 + 冲突检测）            │
│  · 参考区间选择：报告单 > 知识库 > 拒判                     │
│  · 单位归一与换算（UCUM 风格；未登记因子则拒判，不猜系数）   │
│  · 定性结果判定（阴性/-/neg/(−) 记号集求交）               │
│  · H / L / 危急值 / 临界 判定，计算偏离度                   │

        ▼
┌──────────────────────────────────────────────────────────┐
│ Stage 3  解释层（LLM + 约束检索 + 拒答）                   │
│  · 先按 canonical_name 硬过滤 —— 绝不跨指标检索             │
│  · 再按判定结果排维度优先级（偏高→升高意义，偏低→降低意义）   │
│  · 得分低于阈值 → 返回"暂无可靠依据"，不硬编                  │
└──────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ Stage 4  护栏与溯源                                        │
│ 正则拦截诊断/用药/剂量 → 字段级溯源 → 免责声明与局限性说明    │
└──────────────────────────────────────────────────────────┘
```

### 为什么解释层是「约束检索」而不是普通向量 RAG

普通 RAG 是"把 query 扔进向量库取 top-k"，在医疗场景有三个致命问题：

1. **可能捞错项目**——查"肌酐"却召回"尿素"的区间或意义，模型会照着错的依据写出一段自洽的解释，**用户完全看不出来**。
2. **表达不了优先级**——"报告区间 > 知识库区间"这种业务规则，纯相似度排序无法表达。
3. **没有"不知道"这个选项**——top-k 永远返回 k 条，哪怕全都无关。

所以本项目的顺序是 **先硬过滤、再语义排序**：`canonical_name` 由规则引擎**查表**得到（不是模型生成的），
用它做硬过滤保证不串指标；维度权重高于词法相关度，保证"问升高意义不会返回定义"；分数低于阈值直接拒答。

> 顺带说清楚一个常见误解：**参考区间这类结构化事实根本不该用 RAG 查。**
> 它是四维键值查询（项目 × 性别 × 年龄 × 单位），不是模糊检索问题。
> RAG 的用武之地是"解释性文本"，不是"阈值判定"。

## 评测

完整结果见 [`evals/RESULTS.md`](evals/RESULTS.md)。评测集是**代码渲染的合成报告**（20 份 / 276 项，含 4 个危急值 case），不含任何真实个人信息。

评测分三条路径，用来把"判定逻辑"和"知识库数据"的问题分开：

| 路径 | 样本 | 总体准确率 | **危急值漏报率** | 异常总漏报率 | 未判定 |
|---|---|---|---|---|---|
| A1 · 仅报告自带区间（空知识库） | 276 | 98.6% | 100.0%※ | 0.0% | 1 |
| A2 · 仅内置知识库 | 276 | 99.3% | **0.0%** | 0.9% | 1 |
| A3 · 生产路径（报告优先 + 知识库兜底） | 276 | **100.0%** | **0.0%** | **0.0%** | 0 |

※ **A1 那一列的 100% 不是缺陷，是设计使然**：该路径刻意清空知识库，此时系统里不存在任何危急值阈值，
四项危急值只能被判成普通偏高/偏低。这一列的作用是确认"**没有参考数据时系统不会凭空捏造危急值**"，
而不是衡量检测能力。真正有解释力的是 A2/A3。

### 为什么头条指标是「危急值漏报率」而不是平均准确率

**Ramaswamy 等**（*Nature Medicine* 2026;32:1671，[DOI](https://doi.org/10.1038/s41591-026-04297-7)）
在 960 条回答上发现：给模型加入客观检验数据后，
**总体分诊准确率从 54.6% 升到 77.9%，但急症漏判率反而升到 56.2%**。
Zayed 等（*CCLM* 2025）也测出大模型检验开单精确率 68–82%、**召回仅 41–51%**。

把危急值判成正常、和把正常判成偏高，代价完全不对称——前者可能耽误处理，后者只是让用户多问医生一句。
**只报平均准确率的评测是在掩盖尾部风险。**

### 评测跑出来的真实缺陷

写评测的价值在于它立刻抓到了几个静默错误（都已在代码中修复，并补了回归测试）：

| 缺陷 | 后果 | 修复 |
|---|---|---|
| **别名冲突被静默吞掉** | `crp` 抢注了 `超敏C反应蛋白`，导致 `hscrp` 永远解析不到，**用 crp 的区间判 hscrp** | 两阶段索引：本体名优先，冲突记录进 `alias_conflicts` |
| **危急值量纲错配** | 报告用 `%` (44.6)、知识库阈值用 `L/L` (0.60) → 正常值被判成**危急偏高** | 危急值阈值只在单位兼容时套用 |
| 定性记号组合漏判 | 报告印"阴性"、结果写"阴性(-)" → 误判为阳性 | 括号拆分为记号集求交 |
| `mL/min/1.73m^2` vs `m2` | 纯书写差异导致 eGFR 被拒判 | 单位别名补全 |
| ALT/AST 缺危急值阈值 | 685 U/L 只判成"偏高" | 补 500 U/L（标注各院阈值不同） |
| 检索维度被词法分压制 | 查"升高意义"却返回"定义" | 维度权重高于词法相关度 |

另外两项 A2 的"错判"是**刻意保留的正确行为**，没有优化掉：
`apoa1` 是知识库（WS/T 404.3-2012）与评测集的区间定义分歧；
`ckmb` 是系统**正确拒判**——报告用活性法 U/L、知识库按质量法 μg/L 存区间，两者不可换算，宁可放弃判定也不硬套阈值。

## MCP 接入

把"确定性判读"暴露给任何 Agent —— 让 Agent **调用一个可靠的判定器**，而不是相信模型心算参考区间。

```json
{
  "mcpServers": {
    "lablens": {
      "command": "python",
      "args": ["/absolute/path/to/lablens/mcp_server.py"]
    }
  }
}
```

**零依赖**：手写 JSON-RPC 2.0 over stdio，不需要 `mcp` SDK。

| 工具 | 作用 |
|---|---|
| `judge_lab_items` | **核心**：确定性判读。返回每项的 flag、severity 与 `decision_trace` |
| `explain_lab_result` | 通俗解读 + 建议向医生提问的清单（含拒答与护栏） |
| `lookup_indicator` | 查指标定义、LOINC、参考区间、危急值、方法学注意事项 |
| `list_indicators` | 列出知识库收录的指标 |
| `convert_unit` | 单位换算（只做已登记的换算，不猜系数） |

`initialize` 返回的 `instructions` 会明确告诉 Agent：
**需要判断检验值是否异常时应当调用本工具，不要自己推算参考区间。**

## 知识库怎么建的

结构化的东西和解释性的东西**分两层存**，用不同机制处理：

| 层 | 内容 | 存储 | 查询方式 |
|---|---|---|---|
| **KB-1** | 参考区间、危急值阈值、单位换算、别名、LOINC | `data/indicators_*.yaml`（95 项） | 代码查表（四维：项目 × 性别 × 年龄 × 单位） |
| **KB-2** | 单位归一与换算 | `core/units.py` | 纯函数 |
| **KB-3** | 指标临床意义、影响因素、注意事项 | `data/corpus.jsonl`（420+ 条） | 约束检索（先按指标名硬过滤，再按维度排序） |

**参考区间的数据源按可信度排序**：

1. 报告单自带区间 —— 运行时最优先
2. **中国卫生行业标准**：`WS/T 405-2012`（血细胞分析参考区间）、`WS/T 404 系列`（临床常用生化检验项目参考区间）
3. 临床检验操作规程 / 各院检验科公示区间
4. LOINC / UCUM —— 编码与单位标准

每条指标都带 `source` 字段标注到具体标准，并用 `note` 记录**方法学陷阱**：
例如 `ckmb` 的质量法（μg/L）与活性法（U/L）不可直接比较、`ddimer` 的 DDU/FEU 差约 2 倍、
`bun` 的尿素与尿素氮不可混用。这些说明会随判定结果一起透传给用户。

## 合规定位

依据《人工智能医用软件产品分类界定指导原则》（国家药监局 2021 年第 47 号通告）原文：

> "若软件产品的处理对象为**非医疗器械数据（如患者主诉等信息、检验检查报告结论）**，
> 或者其核心功能不是对医疗器械数据进行处理、测量、模型计算、分析，或者**不用于医疗用途**的，
> **不作为医疗器械管理**。"

本项目处理的是**报告文本**（而非分析仪原始数据或病理图像），且不用于医疗用途，
据此定位为**技术演示，非医疗器械**；不面向公众提供医疗服务，未取得也不申请任何医疗器械注册。

**数据处理的默认选择是"不处理"：**

- **默认不落库**——进程退出即忘；趋势存储需用户显式开启，且只写本机文件、只存数值与日期，不含姓名/医院/报告原文
- **内置合成示例**——访客可以直接体验，无需上传任何真实报告
- 上传前提示脱敏；日志不记录报告原文

补充说明：检验报告属《个人信息保护法》第 28 条的敏感个人信息，且
GB/T 39725-2020 要求健康医疗数据"不宜存储在境外服务器"；
《促进和规范数据跨境流动规定》第 5 条的豁免**不含敏感个人信息**。
若使用云端模型 API，请自行评估数据出境合规性；生产环境建议改用本地推理。

## 这个项目不做什么

明确写下来，因为**边界本身就是设计**：

- ❌ 不出诊断结论（不说"您患有××"）
- ❌ 不给用药建议、不写剂量、不做处方相关表述（法规红线，且由代码强制）
- ❌ 不做综合风险评分或"红黄绿灯"分级（容易被认定为辅助决策）
- ❌ 不做生活方式、饮食、运动建议（对标 Quest × Google 的克制范式：
  只解释术语、识别趋势、生成"该问医生的问题"）
- ❌ 不替代医生，不做任何医疗文书

以及**当前的真实局限**：

- 抽取层依赖多模态模型对报告图片的识别，版式特殊的报告可能漏项（因此保留了人工核对入口）
- 知识库 95 项覆盖常见项目，长尾项目会走"拒判"路径
- 危急值阈值各实验室不同，知识库里的值是**常见默认值**，生产环境必须按本院配置
- 评测集是合成数据，尚未用真实脱敏报告验证
